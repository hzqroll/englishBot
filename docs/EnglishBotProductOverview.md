## 1. 产品概述

EnglishBot 是一个面向群聊场景的英语学习机器人，当前同时支持 QQ 群和飞书群。

它不是单一的翻译工具，而是一套围绕“日常使用英语并被及时纠正”的学习产品，包含三类能力：

- 即时语言支持
  - 在群内快速完成中文翻译、英文纠错、整段对话分析
- 群学习闭环
  - 报名、每日学习包、任务提交、复习、周测、周报、晚间总结
- 管理与运维
  - 管理后台、动态配置、任务触发、投递记录、健康检查

当前产品的运行形态包括：

- 用户侧群聊入口
  - QQ 群
  - 飞书群
- 管理侧 Web 后台
  - 管理员登录与配置管理
- 自动化任务系统
  - 按时间自动推送学习内容、总结、周报、周测与备份

## 2. 用户端功能

### 2.1 `@机器人` 即时语言支持

群成员在群里 `@机器人` 发送内容时，系统会根据内容类型自动分流：

- 中文消息
  - 默认走腾讯翻译，直接返回英文结果
- 英文消息
  - 默认走快速英文纠错，返回修正后的英文、中文释义、问题说明
- `大模型润色：...`
  - 对显式提供的整段对话做一次整体分析
  - 输出保留说话人结构的英文版对话
  - 输出按人归类的问题说明
- `分析最近聊天内容`
  - 对最近累计的群聊内容做一次整体分析
  - 输出英文版对话和按人问题说明

其中，整体分析属于高成本功能，和普通翻译/纠错分开使用。

### 2.2 固定学习命令

学习命令默认直接在群里发送，不需要 `@机器人`。

当前支持的固定命令有：

- `报名学习`
  - 把当前用户加入训练营，并初始化等级
- `今日任务`
  - 获取当天的学习包和任务卡片
- `提交任务 <任务ID> <内容>`
  - 提交当天任务，获得分数与反馈
- `复习一下`
  - 拉取当前到期的复习项
- `我的等级`
  - 查看当前等级、活跃度和相关学习证据
- `开始周测`
  - 生成一套属于当前用户的周测试卷
- `答题 <试卷ID> 1:A 2:B ...`
  - 提交整套周测答案
- `本周总结`
  - 获取本周个人学习周报
- `帮助`
  - 查看当前功能与命令说明

### 2.3 对话整体分析入口

整体分析类功能除了 `@机器人` 外，也支持直接在群里发送关键字触发：

- `大模型润色：<对话内容>`
- `分析最近聊天内容`

这两个入口的目标是帮助群成员从“单句纠错”升级到“整段表达复盘”。

### 2.4 被动群聊观察

机器人默认会静默观察群里的普通发言，用于学习分析，不会对每条群聊主动插话。

被动观察目前承担的作用包括：

- 记录普通群聊消息
- 沉淀用户学习证据
- 识别当天是否使用了目标表达
- 为晚间学习进度总结提供素材
- 为“分析最近聊天内容”积累群聊缓存

普通群聊消息不会直接得到机器人回复，但会进入后续学习分析链路。

## 3. 学习系统能力

### 3.1 每日学习包

系统每天会围绕一个主题生成当日学习包，内容包括：

- 学习主题
- 昨日回顾
- 核心词块
- 支持词汇
- 办公室情景对话
- 任务清单

学习包既可以由用户主动通过 `今日任务` 获取，也可以由系统在固定时间自动推送到群里。

### 3.2 昨日回顾与次日回捞

系统会从前一天的高频错误和重点表达中挑选回顾内容，插入第二天学习包，并尽量让任务提示复用这些内容。

这部分能力的目的是把“即时纠错”转成“隔天再次使用”，帮助形成长期记忆。

### 3.3 任务提交与反馈

用户提交任务后，系统会：

- 记录提交内容
- 计算任务分数
- 生成简短反馈
- 发放积分

任务反馈强调鼓励和改进建议，帮助用户持续完成日常练习。

### 3.4 错误沉淀与复习机制

当用户进行英文纠错时，系统会把结果沉淀为可复习对象：

- 错误点
- 错误出现记录
- 复习项

系统会根据复习节奏安排后续回顾，让一次纠错不只停留在当下。

### 3.5 等级评估

当前系统提供两档学习等级：

- `beginner`
- `intermediate`

等级评估会综合以下因素：

- 翻译次数
- 纠错次数
- 任务完成数
- 周测成绩

用户可以通过 `我的等级` 主动刷新和查看当前等级状态。

### 3.6 周测系统

周测面向已报名用户，支持完整的出题、答题和计分流程。

当前周测特点：

- 题目数量可配置
- 题目来源包含历史高频错误和近期学习任务
- 当前题型以客观题为主
- 错题可再次回流到复习体系

### 3.7 周报与晚间总结

系统当前支持三类个人总结：

- 每日纠错整理
  - 晚上汇总当天的词汇/表达问题和语法问题
- 每日学习进度
  - 汇总当天参与情况、学习证据、掌握判断和建议
- 每周学习周报
  - 汇总学习天数、完成率、纠错次数、周测成绩、薄弱点和总结语

这些内容只面向已报名用户生成。

## 4. 自动化与消息推送

### 4.1 定时任务

系统当前有 6 个自动任务：

- `daily_push`
  - 晨间推送今日学习包
- `daily_error_digest`
  - 晚间推送个人错误整理
- `daily_progress`
  - 晚间推送个人学习进度
- `weekly_report`
  - 周报推送
- `weekly_quiz`
  - 周测推送
- `nightly_backup`
  - 数据库备份

这些任务都支持后台手动触发，也支持按 cron 动态调整执行时间。

### 4.2 推送对象

自动推送分为两类：

- 群广播内容
  - 例如每日学习包
- 个人定向内容
  - 例如错误整理、学习进度、周报、周测

个人定向内容会按用户逐条发送，并带上对应的学习卡片。

### 4.3 飞书文档归档

当系统向飞书群发送定时学习卡片后，会尝试把卡片内容同步归档到飞书文档。

当前归档特点：

- 按周创建文档
- 自动追加每日任务、错误摘要、学习进度、周报内容
- 首次创建周文档时可通知指定飞书群

这项能力主要用于飞书侧的长期留档与复盘。

## 5. 多渠道与消息展示

### 5.1 支持渠道

当前产品支持：

- QQ 群
- 飞书群

两侧都能承接：

- 普通 `@机器人` 语言支持
- 固定学习命令
- 被动群聊观察
- 定时任务推送

### 5.2 展示形态

系统当前有三种主要消息形态：

- 纯文本回复
  - 用于翻译、纠错、帮助说明、答题结果等
- QQ 图片卡片
  - 用于任务、周测、周报、晚间总结等结构化内容
- 飞书互动卡片
  - 飞书端对应的结构化学习卡片

### 5.3 渠道差异

当前渠道差异主要体现在展示和接入方式：

- QQ
  - 通过 OneBot 接入
  - 结构化内容优先渲染为图片卡片
- 飞书
  - 通过 WebSocket 接入
  - 结构化内容渲染为互动卡片
  - 额外支持飞书文档归档

## 6. 管理后台与运维能力

### 6.1 管理后台入口

系统提供 Web 管理后台，当前主要入口包括：

- `/admin/login`
- `/admin`
- `/healthz`
- `/readyz`

### 6.2 后台核心页面

当前后台具备以下能力：

- 仪表盘
  - 查看整体指标和最近任务执行情况
- 用户列表
  - 查看用户基本数据
- 群组管理
  - 管理 QQ / 飞书群
  - 配置是否启用
  - 配置 QQ 管理群
  - 配置群级消息渲染模式
- 运行时设置
  - 查看和修改动态配置
  - 查看当前生效配置
- 作业记录
  - 查看定时任务执行情况
- 投递日志
  - 查看消息推送是否成功
- 调试页
  - 无需真实群聊即可测试翻译、纠错和部分消息处理流程

### 6.3 手动触发能力

后台支持手动触发以下任务：

- 每日学习包推送
- 每日纠错整理
- 每日学习进度
- 周报
- 周测
- 夜间备份

这使得运营和开发在联调、演示和排障时不必等待定时任务自动执行。

## 7. 数据沉淀与分析能力

系统当前不仅回复消息，也会把学习行为沉淀为结构化数据，供复习、总结、统计和后台展示使用。

当前主要沉淀对象包括：

- 消息事件
  - 记录群消息、`@机器人` 消息、命令消息
- 互动结果
  - 记录翻译、纠错、整体分析等回复结果
- 错误点与错误出现记录
  - 支持后续复习、统计高频问题
- 对话学习证据
  - 记录用户在普通群聊中的学习痕迹
- 复习项与次日回捞候选
  - 支持复习安排和昨日回顾
- 每日学习快照
  - 保存每日进度结论
- 卡片快照
  - 保存已生成的结构化卡片内容
- 周测会话与答案
  - 保存试卷、答题和分数
- 周报
  - 保存每周汇总结果
- 作业运行记录与投递日志
  - 记录任务执行和消息发送情况

这些数据共同支撑当前产品的“学习闭环”和后台管理能力。

## 8. 典型使用路径

### 8.1 新用户开始学习

一个典型的新用户路径是：

1. 进入学习群
2. 发送 `报名学习`
3. 发送 `今日任务`
4. 完成并提交任务
5. 晚上接收错误整理和学习进度
6. 周末参与周测并查看周报

### 8.2 日常即时使用

群成员日常使用路径通常包括：

1. 遇到中文表达需求时 `@机器人` 获取英文翻译
2. 遇到英文表达问题时 `@机器人` 获取纠错结果
3. 需要复盘整段表达时使用 `大模型润色：...`
4. 想整体复盘最近群聊时使用 `分析最近聊天内容`

### 8.3 管理员运维路径

管理员日常运维路径通常包括：

1. 登录后台查看仪表盘
2. 管理群组启用状态和配置
3. 调整运行时设置
4. 用调试页验证消息处理
5. 手动触发定时任务
6. 查看作业记录和投递日志排障

## 9. 当前边界与限制

当前版本需要明确的边界包括：

- 学习命令与 `@机器人` 分工不同
  - 学习命令默认直接发送
  - `@机器人` 主要用于语言支持和整体分析
- 晚间总结、周测、周报主要面向已报名用户
- `分析最近聊天内容` 依赖最近群聊缓存，并且有最小句数门槛
- 最近群聊缓存是进程内缓存
  - 服务重启后会重新累计
  - 跨天后会按新一天重新计算
- 周测当前以客观题为主
- 外部服务未配置时，部分能力会走降级逻辑
  - 适合开发调试，不适合作为正式生产效果
- 当前产品核心场景仍然是群聊学习，不是私聊陪练产品
